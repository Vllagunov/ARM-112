# ТОЭС 112 — учебный тренажёр оператора ДДС

## Команда «Аэлин»

Прототип разработан в рамках хакатона «Лидеры цифровой трансформации», кейс № 09 — учебное программное обеспечение для подготовки оператора диспетчерской службы.

## 1. Назначение проекта

ТОЭС 112 — прототип автоматизированного рабочего места оператора 112 с голосовым вводом и управляемым учебным сценарием.

Проект предназначен для обучения и тренировки операторов диспетчерской службы с помощью имитации входящего вызова и последовательного прохождения контрольных вопросов.

Демонстрационный сценарий: **«Пожар в квартире»**.

Прототип не предназначен для обработки реальных экстренных вызовов.

## 2. Текущая версия АРМ

Основной графический файл проекта:

`arm_112.py`

Версия: **0.5**.

При запуске открывается графическое окно:

**АРМ ОПЕРАТОРА 112 — TOES 112**

Размер окна по умолчанию — 1400 × 850 пикселей. Минимальный размер — 1100 × 700 пикселей.

Интерфейс имитирует рабочее место оператора диспетчерской службы и содержит основные элементы управления учебным вызовом.

## 3. Функциональные возможности

В графическом АРМ реализованы:

- отображение состояния входящего учебного вызова;
- таймер вызова;
- кнопка «ПРИНЯТЬ ВЫЗОВ»;
- кнопка «ЗАВЕРШИТЬ»;
- кнопка «ГОВОРИТЬ» для голосового ввода;
- кнопка «ТЕСТ СЦЕНАРИЯ» для проверки сценарной логики без микрофона;
- отображение данных заявителя;
- контрольные вопросы;
- подсказки оператору;
- карточка происшествия;
- область карты;
- журнал разговора;
- индикаторы состояния Whisper, аудио и ScenarioEngine.

Интерфейс позволяет оператору последовательно проходить учебный сценарий и отслеживать результаты обработки своих ответов.

## 4. Логика работы АРМ

Основной рабочий контур графического приложения:

```text
Входящий учебный вызов
        ↓
ПРИНЯТЬ ВЫЗОВ
        ↓
ГОВОРИТЬ
        ↓
Запись речи с микрофона
        ↓
SpeechToText
        ↓
Распознавание речи Whisper
        ↓
Передача распознанного текста
        ↓
ScenarioEngine
        ↓
Проверка ответа оператора
        ↓
Результат сценария
        ↓
Обновление интерфейса
        ↓
Следующий контрольный вопрос
```

При принятии вызова создаётся экземпляр `ScenarioEngine`, который управляет прохождением сценария.

При нажатии кнопки «ГОВОРИТЬ» система запускает отдельный поток записи и распознавания речи. Распознанный текст передаётся в метод:

```python
self.engine.process(text)
```

Сценарный движок анализирует фразу оператора, определяет, соответствует ли она текущему этапу, и возвращает результат обработки.

В зависимости от результата АРМ обновляет текущий этап и журнал разговора.

## 5. Обработка распознанной речи и голосовые подсказки

Для распознавания речи используется модель Whisper с поддержкой русского языка.

Если распознанная фраза не соответствует текущему этапу сценария или речь не удалось распознать, тренажёр предлагает оператору повторить вопрос.

При этом оператор получает голосовую подсказку с примером того, что необходимо сказать.

После повторной попытки система снова распознаёт речь и передаёт результат сценарию.

Такой механизм позволяет оператору тренироваться в формулировании вопросов и последовательно проходить контрольные точки сценария.

Работа распознавания речи и сценарной логики проверялась при запуске и тестировании модели.

## 6. Сценарный движок

Файл:

`scenario_engine.py`

Версия: **0.5**.

Сценарный движок отвечает за управление контрольными точками учебного сценария, проверку фраз оператора и формирование ответов заявителя на основе заданных сценарных данных.

Для демонстрационного сценария «Пожар в квартире» предусмотрены следующие этапы:

1. Выяснение того, что произошло.
2. Уточнение адреса происшествия.
3. Выяснение, есть ли люди внутри помещения.
4. Выяснение наличия пострадавших.
5. Уточнение места возникновения пожара.
6. Выяснение степени задымления.

Переходы между этапами определяются логикой `ScenarioEngine`.

Данные сценария загружаются из файла:

`scenarios/training/fire_apartment_data.py`

Сценарный движок отделён от графического интерфейса, что позволяет использовать его в других компонентах проекта.

## 7. Распознавание речи

Файл:

`speech_to_text.py`

Версия: **1.0**.

Компонент предназначен для записи и распознавания речи оператора.

Используемые библиотеки:

- `sounddevice`;
- `soundfile`;
- `whisper`.

Основные функции:

- запись звука с микрофона;
- сохранение записи во временный WAV-файл;
- передача аудиозаписи модели Whisper;
- распознавание русской речи;
- удаление временного аудиофайла;
- возврат распознанного текста для дальнейшей обработки.

Модель Whisper загружается с параметром:

```python
base
```

Распознавание выполняется с указанием русского языка:

```python
language="ru"
```

## 8. Синтез речи

Файл:

`text_to_speech.py`

Версия: **1.0**.

Компонент предназначен для автономного синтеза речи с использованием библиотеки `pyttsx3`.

В текущей версии графического АРМ `arm_112.py` компонент `TextToSpeech` напрямую не подключён. Голосовые подсказки, используемые в АРМ, относятся к реализованной логике приложения.

## 9. GigaChat

Файл:

`gigachat_client.py`

Версия: **0.3**.

Компонент предназначен для взаимодействия с GigaChat и поддерживает работу с историей диалога.

Используются:

- `GigaChat`;
- `Chat`;
- `Messages`.

В текущей версии графического АРМ `arm_112.py` компонент `GigaChatClient` напрямую не импортируется и не вызывается.

Таким образом, GigaChat является отдельным компонентом проекта и не входит в основной рабочий контур графического АРМ версии 0.5.

## 10. Отдельный голосовой контур toes_core.py

Файл:

`toes_core.py`

Версия: **0.7**.

`toes_core.py` представляет собой отдельный голосовой контур проекта, предназначенный для взаимодействия компонентов распознавания речи, сценарного движка, GigaChat и синтеза речи.

Архитектура отдельного голосового контура:

```text
Микрофон
   ↓
Whisper
   ↓
ScenarioEngine
   ↓
GigaChat — опционально
   ↓
TTS
```

В компоненте используются:

- `sounddevice`;
- `scipy`;
- `faster-whisper`;
- `pyttsx3`;
- `gigachat_client`;
- `scenario_engine`.

Для GigaChat предусмотрен режим:

```python
GIGACHAT_EMOTION = True
```

При отключении GigaChat используется непосредственно ответ сценарного движка.

Отдельный голосовой контур не является прямой частью графического АРМ версии 0.5.

## 11. Тестирование сценария

В графическом АРМ предусмотрен отдельный режим:

**▶ ТЕСТ СЦЕНАРИЯ**

Он позволяет проверить последовательность контрольных вопросов без использования микрофона.

Для проверки сценария предусмотрены следующие тестовые вопросы:

```text
Что произошло?
Назовите адрес.
Есть ли люди внутри?
Есть ли пострадавшие?
Где пожар?
Есть ли сильный дым?
```

Тестовый режим позволяет проверить прохождение контрольных точек и работу сценарной логики без использования голосового ввода.

## 12. Установка и запуск

Для работы графического АРМ необходимы Python и библиотеки, используемые в его фактических импортах.

Основные зависимости:

```text
tkinter
sounddevice
soundfile
whisper
```

`tkinter` является стандартным модулем Python для создания графического интерфейса.

Для отдельного голосового контура `toes_core.py` дополнительно используются:

```text
sounddevice
scipy
faster-whisper
pyttsx3
gigachat
```

Точный перечень устанавливаемых пакетов определяется составом файлов, включённых в финальную поставку проекта.

Запуск графического АРМ выполняется командой:

```bash
py -3.12 arm_112.py
```

После запуска открывается графический пульт «АРМ ОПЕРАТОРА 112 — TOES 112».

## 13. Демонстрация проекта

Для демонстрации основного рабочего контура необходимо:

1. Запустить `arm_112.py`.
2. Нажать кнопку «ПРИНЯТЬ ВЫЗОВ».
3. Нажать кнопку «ГОВОРИТЬ».
4. Произнести контрольный вопрос.
5. Дождаться распознавания речи.
6. Проверить результат обработки в журнале.
7. При необходимости повторить вопрос, следуя голосовой подсказке.
8. Продолжить прохождение сценария до завершения.

Для демонстрации сценарной логики без микрофона можно использовать кнопку «ТЕСТ СЦЕНАРИЯ».

## 15. Ограничения текущей версии

ТОЭС 112 версии 0.5 является прототипом учебного тренажёра.

Графический АРМ `arm_112.py` использует голосовой ввод через `SpeechToText` и сценарный движок `ScenarioEngine`.

Отдельные компоненты `GigaChat`, `TextToSpeech` и `toes_core.py` присутствуют в проекте, но не являются прямыми подключениями графического АРМ текущей версии.

Прототип предназначен исключительно для учебных и демонстрационных целей и не предназначен для обработки реальных экстренных вызовов.
